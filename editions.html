Core & Advanced

One musical foundation with two different distribution policies: an eventual publicly available standalone Core instrument, and the artist's documented-but-private Advanced system.

In brief

Core is planned for a public release once compatibility, dependencies and licensing are verified. Advanced is an individually tailored performance system and is not offered for download.

Core: an open instrument, not a finished download

The aim for TMC Core is a standalone norns instrument that the wider community can use without specialised external MIDI or audio devices. The current plan is to share the software free, with appropriate attribution to original libraries and engine authors.

Not release-ready Code separation, performance profiling, licence review and hardware compatibility testing remain to be completed. Public downloads are deliberately absent.

Advanced: a specialised personal ecosystem

Advanced extends TMC into an eight-layer and external MIDI performance environment. The working setup includes additional ES-8 outputs, a TX-6 mixer, Bitbox Micro percussion with eight Objects pads, and external recording and processing. The particular choices reflect the artist's hardware and listening practice.

Advanced will be documented, not published as source code. Readers may learn how musical relationships, percussion decisions and routing evolved, without a promise of plug-and-play compatibility or a software download.

How the editions relate

Shared musical thinking

Conductor concepts, microtonal organisation, AOS relationships and the distinction between large-scale temporal permissions and local behaviour.

Advanced-specific work

Hardware-addressed MIDI, external eight-pad Objects percussion, more independent outputs and the personal performance/mixing chain.

CM3, CM3+ and CM4S

The official monome norns guide describes original norns units with CM3 and CM3+ compute modules. More recent norns releases describe CM4S support. Our earlier conversation sometimes used “CM3S” informally; it should not be treated as a verified model designation.

The public Core target will be stated only once actual builds have been tested on identified hardware. A successful local code test does not establish smooth performance on every aluminium norns.

Before Core can be released

  • Separate standalone Core from hardware-specific Advanced configuration.
  • Verify code and sample licences, credits and required dependencies.
  • Test installation, startup, audio, controls, recovery and CPU behaviour on declared hardware.
  • Record firmware versions and publish reproducible installation steps.
  • Make limitations visible and provide a clear changelog.
