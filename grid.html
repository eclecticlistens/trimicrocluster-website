Reading the surface

A conventional sequence display invites you to follow a playhead. TMC's map asks a different question: where is the musical reference, what is happening around it, and where might a small intervention be useful?

The Grid 128 is shown here in landscape orientation: sixteen columns and eight rows. One layout proposal from 30 September reserves the upper seven rows for voice lanes and the bottom row for global controls. It gives ARP 1 and ARP 2 a shared, focused display lane without combining the two sound voices. The illustration below explains that proposal; it is not a verified button map for the latest installed build.

An 8 × 8 Launchpad Mini Mk3 was used during development. The full sixteen-column surface and the controller's smaller viewport are therefore different things. Hardware adaptation should not change the musical meaning of a gesture.

What the light means

The central visual rule is simple: Anchor should remain the brightest reference. Orbit and Shimmer need to be visible without making that reference disappear into an equally bright field. Variation in brightness supplies a hierarchy rather than a colour code for different instruments.

Light can also distinguish an established reference from recent activity. Earlier design discussions explored dim remembered traces, brighter active events and dark positions where there was nothing meaningful to show. The distinction is useful: a pad's brightness is not automatically a measure of audio volume, and a glowing position need not mean a note is sounding at that instant.

Monome's norns API accepts LED levels from 0, off, to 15, fully bright. The warm amber used on this website is a visual interpretation; physical grid generations differ in LED colour. Source notes ↓

Tap, hold, double-tap

The late-September refinement gave different intentions different gestures. In the 30 September implementation report, a short tap focuses a lane, a held press prepares a temporary melodic nudge and commits it on release, and a double-tap requests a Shimmer intervention.

Shimmer request

Request a brief intervention. It is not a second, permanent Anchor.

These melodic interventions were described for the Tonal and ARP paths. They should not be assumed to have the same effect on Drone, SubHarm or every external percussion pad.

The reported Shimmer refinement uses the current Field Shimmer, brought into the pitch field, rather than treating the touched position as an arbitrary new pitch. It is a one-use pending intervention with an expiry. Nudge and Shimmer replace one another rather than building a queue of competing requests.

Timing details from the 30 September implementation report

The reported long-press threshold was at least 0.65 seconds, committed on release. Double-tap recognition used two short taps of no more than 0.30 seconds each, with a gap of no more than 0.35 seconds. These values come from the dated implementation report, not a fresh audit of the running build.

The user subsequently reported that the grid was working on the 8 × 8 controller, while native 128 hardware testing was still to follow. That report does not establish that every later page or controller retained the same thresholds.

An invitation, not a command

The approved Nudge design changes attraction for a short time. It does not drag the Anchor to a new position or rewrite the notes already sounding. The next eligible notes can be drawn towards a valid nearby pitch, while the rest of the instrument continues under its existing rules.

Accepted notes matter. An idle layer is not awakened just because the performer nudges it. IDLE does not consume the note allowance, although the fifteen-second expiry still runs. This preserves the Conductor's permission logic instead of making every touch an instruction to break the silence.

A new nudge replaces the previous one. It does not stack. The gesture also leaves the TRI behaviour and an already-sounding note unchanged. Its purpose is a temporary suggestion within the system, not a new operating mode.

The bottom row sets a wider context

The layout proposal reserves the bottom row for controls that act beyond a single pitch position. Still, Drift, Shine and AUTO belong to this wider behaviour-control discussion. The grid and norns parameter menu were intended to share state rather than behave as separate versions of the instrument.

A global behaviour choice is different from a melodic nudge. One changes the wider context; the other briefly influences forthcoming material inside it. Likewise, AUTO is a control setting, not an extra AOS role.

Exact column assignments are deliberately not printed on the example map: the page history changed, and the currently running build needs to be checked before publishing a fixed button-by-button manual. The later two-bank mixer for TMC layers and Bitbox pads was a separate development plan, not a feature to assume from this map.

A visual language that developed over time

Early triangle, seed and idle-shape explorations helped establish how a reference could remain recognisable while other activity changed around it. They belong to the design history, not to a claim that every such shape is displayed simultaneously on a later row-based grid.

The same distinction matters for other screens. The norns display can report exact state; the performance grid offers a spatial, tactile view. The later slow, triangle-led and flocking visual ideas were another line of exploration, not evidence that those animations were already running on the grid.

The important outcome is the relationship between seeing, touching and listening. A performer can recognise the reference, offer a small suggestion and hear how the instrument responds — without having to turn an autonomous instrument into a note-by-note sequence.

Design history, evidence and hardware sources

28 September 2026: the user required Anchor to remain brightest. Brightness ranges suggested around that discussion were proposals, not verified current constants. The earlier long-press-to-relocate-Anchor idea is superseded here by the more specific 30 September Nudge design.

30 September 2026, user-approved Nudge rules: temporary attraction over three accepted notes or fifteen seconds, weakening on use, replacing rather than stacking, without changing sounding notes or TRI or waking IDLE. The user subsequently reported that the grid was working on the 8 × 8 controller, with native 128 testing still to follow.

30 September implementation report: the reported gesture thresholds and one-use Shimmer rules accompany the approved Nudge design. These are implementation reports, not a current source-code audit.

30 September layout proposal: Drone, SubHarm, Rings Cells, Tonal 1–3, a focused ARP lane and a global row. This exact ordering is preserved here as a historical design proposal. The recovered material does not establish final adoption or the current installed map.

12 October 2026: the two-bank Grid mixer was planned after the percussion work. It is not presented as part of the tested September controls.

Hardware references: monome's norns Grid API documents the 0–15 API brightness range; the grid edition history documents size and lighting differences. Neither source establishes TMC-specific behaviour.
